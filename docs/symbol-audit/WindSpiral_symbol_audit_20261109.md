# WindSpiral 首批项目图符审计（实图审核版，2026-11-09）

**文件地位**：更新原《WindSpiral 首批项目图符审计》，为当前项目模块首批图符的唯一审核记录。不是已合并入软件的生产映射，也不是对正式公布航图图式的最终合规声明。与机器索引 `WindSpiral_首批图符审核索引.csv` 为同一结论，CSV用于后续编码读取，本文用于审核解释。

## 一、审计证据及范围

1. 由用户提供的7张原始图形 PNG（`Obst`、`ObstWithLight`、`VOR`、`NDB`、`DME`、`NVORDM`、`NDME`），均含原始图形、定义原点红十字、边界蓝虚线、单位和几何外包框。
2. 同批索引 `symbol-index.csv`，七行记录均来自 WindSpiral 原库 SHA256 `AB3141FF3C9D173670C57600ECFA77B28E5625FC0EB1C8C06E37F08F4D8FF5F1`。
3. GitHub `docs/symbol-audit/block-table.json`（AutoCAD 2026 API实测）；`project-block-provenance.json`（项目库四个块来源）；`CadDrawing.Project.cs`（颜色继承、尺寸与插块）；`CadDrawing.BaseMap.cs`（图形身份与CAD更新）。
4. 中国民航局 MH/T 4019—2012《民用航空图编绘规范》，附录B表B.7（导航设施）、B.9（障碍物）；第4.7.5款图形中心点位置原则。官方文本：https://www.caac.gov.cn/XXGK/XXGK/BZGF/HYBZ/202111/t20211109_209970.html 。附录B为资料性附录。

**核查限制**：规范的文字、图例表名称及“人工障碍物位置以底部圆点为准”已核对，官方规范 PDF 的图例截图本轮无法成功取得。因此不能称 VOR、NDB、DME、VOR/DME 四张图已逐笔划正式通过图例对照；当前可开展**内部 CAD 插入验证**，正式航图输出前仍须核对规范原图。切勿把块名或WindSpiral来源视为合规证明。

## 三、CAD 图块定位与变换规则

项目数据投影点为 `P=(X,Y,Z)`；图块源定义的专业锚点为 `a=(ax,ay,az)`，插入比例为 `s`，旋转矩阵为 `R`。要求显示后锚点落于真实位置，即 `P = insertion + R(s*a)`，因此插入点必须为 `insertion = P - R(s*a)`。不能反过来调整经纬度或项目DataId来适应图块。

- `Obst`、`ObstWithLight`、`NDB`、`DME` 以内部 Circle.Center 或 DBPoint 精确重合的 `(0,0,0)` 为锚点，可直接插入P。
- `VOR` 在内部无定位点实体的情况下，按实际图面中心的几何证据暂用原点P，后续用规范图例及CAD实例复核，不把外包框中心自动视作专业锚点。
- `NVORDM`、`NDME` 内部圆心相对定义原点有约4.486e-5个原生长度单位的X偏移。若要求圆心严格落于P，按上述公式处理偏移；不得擅自移动源块定义里的实体。第一批只考虑`NVORDM`。
- 原块单位有 `Meters`、`Undefined` 等混合，且原生宽度从约0.13到超千单位，均是源文件几何长度，**不是实体设施的占地尺寸，也不是最终屏幕符号尺寸**。若使用统一图面显示宽度 `W`，每块比例 `s=W/w_native`，不得再叠加一次未核实的INSUNITS自动缩放。插入后核对目标DWG中实际外包框，避免双重换算。
- 块图形与独立的名称文字尺寸分开。现阶段项目基础标注默认高度500个模型单位，不能用500作为符号宽度，不能将原源块属性`Altitude`自动与项目“只标识编号”的要求叠加。

## 四、当前模块的唯一业务映射边界

正式项目基础数据中，“障碍物”只应拥有一个图块实例及其独立编号；该障碍物是否有灯不能靠高程等资料推断。因此第一批只启用 `Obst` 作为普通障碍物，`ObstWithLight` 待以后明确灯光状态再用。

导航台 VOR / NDB / DME 暂采用上述同名块进行内部CAD插图校验；`VOR_DME` 优先尝试 `NVORDM` 作为一个整体图符，不再同时插一个 VOR 和一个 DME 完整图块。`NDME` 不自动映射任何当前业务类型。

LOC、GP、MB、GBAS 目前业务类型允许录入，但尚无规范图像证据足以确定 WindSpiral 对应块。本轮不编造映射、不静默替换为 VOR 等错误图符；如果暂用基础点作为项目内部占位，必须明确该点非正式专业图符。

每个业务记录采用已有 `ProjectId/Category/DataId`、实体组标签和手工修改保护。正常新增/修改/删除改变对应的一个图符和一段独立文字；人工修改则保留冲突保护。数据重复导入不能重复插图。项目和程序图层保持分离；不得把当前程序级`Flyby/Flyover/Reporting`硬套到项目导航台数据。

## 五、图层、颜色、可维护性

1. 原始库只读，目标DWG中克隆的块定义副本里，对应项目图元归入第0层并设为ByBlock；图块引用自身设置业务图层及ByLayer，名称DBText跟随相同业务图层ByLayer。应检查 `Hatch` 和嵌套图元是否都能够随图层改色。
2. 导入图块必须按来源文件SHA和原始块名识别，不能仅以CAD块名相似就复用。当前四块精简库可复用；如新增 `NVORDM`，须提供从原库经审计的来源链和新的项目库SHA，不可使用原四块校验值假装库未改。
3. 初始插入、反复同步、保存重开、用户改色与字体、删除和重新导入，均复用现有BaseMap图形管理机制，不建立第二套图符数据数据库。
4. 不设置“图符宽度”“块内颜色”“插入点偏移”等用户编辑窗。与符号规范相关的图面显示属性由底层统一控制，设计员依然可以通过原生AutoCAD编辑，并受到人工修改保护。
