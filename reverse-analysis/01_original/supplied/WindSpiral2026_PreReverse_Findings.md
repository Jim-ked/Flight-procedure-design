# WindSpiral2026 逆向前文档核查记录

## 软件自述

根 README 将 WsTools 定位为飞行程序设计 CAD 插件及辅助工具。WindSpiral2026 是其中的飞行程序设计 CAD 插件，C# 开发，通过 CAD `netload` 加载并用 `wstools` 唤起面板。

软件说明称基础版面向学生和飞行程序初学者，用于算法验证、项目实践和应用分析，并明确要求使用者自行对计算结果负责。因此不能预设其实现覆盖全部规范细节。

## 帮助结构

帮助中心公开 10 个传统程序功能、5 个 PBN 功能、4 个辅助窗口，以及若干无窗口 CAD 命令。总体交互仍以“填写参数 + CAD 拾取 + 计算/绘制/评估”为主。

## 关键业务线索

- `FormDepartureEvl` 已经把传统离场分成跑道数据、定高转弯、定点转弯、全向离场，而不是单一“离场保护区”。
- 定点转弯依赖用户在图面确定 TP、KK'、C，说明定位容差与离场转弯之间的衔接目前仍含显著人工操作。
- Fly-by 帮助明确：前后航段保护区宽度不同时，使用风螺旋衔接。
- Fly-over 帮助明确：ATT=0 时外边界与 PBN 定高转弯保护区相同。
- 传统程序转弯有“包络线”按钮，需要人工选取多条已画多段线生成包络区，是明显可研究自动化的位置。
- `xInfo` 可以展开显示实体 XData(JSON)，说明 CAD 实体可能携带结构化业务数据，应作为组件间联系重点追踪。
- `config.xml` 显示 WindSpiral、FlyBy、FlyOver 共享 `turnParameterControl1` 语义，支持底层转弯计算组件复用的判断。

## 文档不一致

帮助维护 README 声称有 20 个窗口并列出 FormMSD，但实际只有 19 个功能 HTML 页面；FormMSD.html 不存在、首页无命令，仅保留 images/FormMSD.png。

config.xml 还出现帮助中心未公开的 FormRouteCheck、FormOasEvl、FormPaoasEvl、FormAn14Evl、FormAn14Next2 等节点，需要判断是隐藏/遗留功能还是其它组件留下的配置。

## 对逆向工作的约束

帮助文件只能作为作者意图和 UI 语义证据。最终必须由 DLL 静态/动态分析验证。尤其保护区衔接、障碍物评价、不同转弯类型和导航方式的分支不能从帮助文本直接推定代码实现。
