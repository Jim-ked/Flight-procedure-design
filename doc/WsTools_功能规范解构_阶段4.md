# WsTools 功能—规范—算法解构（阶段4）

范围：B3 RNP APCH、B4 PBN-ILS。  
规范基线：AC-97-FS-005（2020）。  
辅助历史资料：`Misc/1-RNAV ILS 2017.pdf`、`Misc/2-RNAV+ILS(Day3).pdf`。两份资料用于解释旧课题组的软件设计背景，不替代现行规范；旧软件实际实现最终仍以 DLL/IL/运行结果为准。

## 1. 本阶段的主要认识

B3 和 B4 已经不是单一几何命令。

B3 的实际界面包含：
- 跑道数据
- 程序参数
- LNAV复飞计算
- APV复飞计算
- 附加设置

这说明 B3 实际在一个窗口中组合了 RNP APCH 的 LNAV 非精密进近逻辑、Baro-VNAV/APV 垂直引导逻辑和复飞计算，而不是简单绘制一条 RNP 保护区。

B4 的界面则明显围绕：
- 跑道数据
- OAS面参数
- HL检查
- 障碍物评估
- CAD绘制
- KML输出

展开。其 `config.xml` 中绝大部分 OAS 参数和传统 OAS/精密进近模块高度相似，同时 `Misc` 中保留了专门的 RNAV-ILS 培训资料和 PBN-ILS 图形文件。因此 B4 很可能是在传统 ILS OAS 引擎之上增加 PBN 中间航段和 PBN 复飞转弯衔接规则的专项工具，而不是另起一套 OAS 算法。

## 2. B3 RNP APCH

### 2.1 功能定位

帮助文件称：

`Y53_RNP_APCH`

用于 RNP APCH（含 APV / Baro-VNAV）进近程序保护区构建与障碍物评估。

窗口截图显示五个页签：
1. 跑道数据
2. 程序参数
3. LNAV复飞计算
4. APV复飞计算
5. 附加设置

因此 B3 至少同时覆盖两套最低标准：
- LNAV 非精密进近
- LNAV/VNAV（Baro-VNAV）APV

两者共享 RNP APCH 的水平导航保护逻辑，但垂直超障方法不同。

### 2.2 跑道数据

`config.xml` 中可见：
- 机场类别
- 机场标高
- 温度
- 灯光长度
- 跑道入口坐标
- 跑道末端坐标

跑道入口和末端显然用于建立局部程序坐标系。

机场标高、温度不仅是显示信息，它们会直接影响 Baro-VNAV 的有效 VPA、TAS 和高度损失修正。

### 2.3 RNP APCH 的 LNAV 最后进近

规范中的 RNP APCH 非精密进近要求：
- 最后进近航迹原则上与跑道中线对正；
- 最后进近最佳长度为 9.3 km（5 NM）；
- 通常不应超过 18.5 km（10 NM）；
- 固定翼 FAF 至跑道入口及最后航段最小长度不得小于 5.6 km（3 NM）；
- 主区最低 MOC 为 75 m；
- 最后进近保护区需要从 MAPt 处的保护区宽度按 PBN 衔接规则形成。

因此 B3 中所谓“最后进近段 RNP、长度”等参数不能只理解为一个矩形保护区宽度。实际算法应至少包含：
- FAF/MAPt 位置；
- GNSS 对应 XTT、ATT、1/2AW；
- 主区/副区；
- FAF 至 MAPt 的宽度连接；
- 中间段与最后进近段的衔接；
- 障碍物所在区域判断和 75 m MOC。

### 2.4 LNAV 复飞计算与 A2 的直接关系

B3 配置中存在：

- `textBoxNIAS = 380`
- `textBoxNAlt = 900`
- `textBoxNTemp = 15`
- `textBoxNWind = 19`
- `textBoxNTime = 18`
- `textBoxNDist = 2300`

这组参数的形态与 A2 “非精密 SOC 计算”几乎完全一致。

A2 帮助明确：
- 根据 IAS、高度、温度计算 TAS；
- 加 19 km/h 顺风；
- 以指定时间计算 MAPt 后的过渡距离；
- 计算 SOC。

规范对 SOC 的完整逻辑是：
- MAPt 由导航台/定位点定义时，SOC = MAPt 总容差 + 过渡距离；
- MAPt 由距 FAF 的距离定义时，简化法采用 15 s 的过渡距离；
- MAPt 定位点容差还需要考虑飞行员反应距离。

旧帮助把某些情况简化成 18 s，应由代码确认它是否把 3 s 反应时间和 15 s 过渡时间合并。

因此 B3 的 LNAV 复飞页很可能直接嵌入或复制了 A2 的 NPA SOC 算法。

### 2.5 LNAV 复飞保护区

规范明确：
- MAPt 定义为飞越航路点；
- MAPt 最早位置由 MAPt 处 ATT 决定；
- 从该点起保护区向复飞航迹两侧按 15°扩张；
- 直到达到 MATF 最早位置处的主区+副区宽度。

对于 SBAS/RNP APCH 场景，系统模式变化还可能导致复飞保护区半宽在不同位置发生变化。

因此 B3 的复飞保护区不应被逆向成简单的“从 MAPt 向后画一个梯形”，而应追查：
- MAPt 的 ATT；
- 15°扩张；
- MATF/MAHF；
- 保护区宽度切换；
- 转弯时调用 B1/B2 或一般 PBN 转弯算法的关系。

### 2.6 Baro-VNAV/APV 程序参数

`config.xml` 暴露：
- `textBoxIfSegLen = 10000`
- `comboBoxVPA`
- `textBoxFafAlti = 900`
- `textBoxTCH = 15`
- `comboBoxHi`

这些参数与规范 Baro-VNAV APV 航段高度吻合。

规范规定：
- 最佳 VPA 约为 3°；
- 有效 VPA 会随温度和机场标高变化；
- 最低温时有效 VPA 不得低于 2.5°；
- 最高温时有效 VPA 应不高于 3.5°；
- 标准 TCH/基准高为 15 m；
- APV 航段包含最后下降航段以及复飞起始、中间航段。

所以 B3 的“机场温度”和 VPA 应存在真实联动，不应视为静态显示参数。

### 2.7 APV OAS 的真实结构

Baro-VNAV 的 APV OAS 与 ILS OAS 不是同一套面。

规范中的 APV OAS 包括：
- 最后进近面 FAS；
- 地面平面；
- 复飞 Z 面；
- 相应的侧面。

其横向边界直接借用 LNAV 保护区：
- FAS 内侧/低侧与 LNAV 主区边界相关；
- 外侧/高侧与 LNAV 副区外侧边界相关。

这非常重要，说明 B3 很可能是“LNAV 水平保护区 + APV 垂直面”的组合器。

### 2.8 Hi 参数

规范根据高度把 APV 最后进近面的 `Hi` 分成：
- 75 m
- 105 m
- 120 m

对应不同高度层。

`config.xml` 中存在 `comboBoxHi`，很可能就是用于选择或控制这一分段。

但旧代码是否自动根据机场/中间航段 OCS 高度选择 Hi，还是把选择权留给设计人员，目前不能仅靠配置断言。

### 2.9 FAS 计算

规范明确给出 APV FAS 的关键计算：

- FAS 坡度由 FAP 高度、温度修正量、Hi 和 VPA 共同决定；
- FAS 在入口高处的起点包含 ATT；
- FAS 面高随沿航迹距离线性变化；
- 高于 5000 ft、10000 ft 时需要换用不同 Hi 重新计算。

因此逆向 B3 时应直接寻找：
- `tan(VPA)`
- `Hi`
- `ATT`
- FAP height
- 温度修正量
- FAS 起点
- FAS 斜率
- 5000/10000 ft 分段

而不是只追 CAD Polyline。

### 2.10 APV 复飞计算与 A2 精密 SOC 的复用迹象

B3 中还存在：

- GP
- Xz
- DH
- Airport Elevation
- Aircraft Category
- HLm
- HLr
- HL correction

这些与 A2 “精密 SOC 计算”基本一致。

特别是：
- A/B 类 Xz 基础位置约为 -900 m；
- C 类约 -1100 m；
- D 类约 -1400 m；
- 高机场和较陡 VPA 需要修正；
- HL 随航空器类别变化。

这说明 B3 的 APV 复飞页很可能复用了 A2 的精密 SOC / HL 算法。

### 2.11 HL 默认值与规范可以直接对上

配置中 D 类相关默认值：
- HLr = 26 m
- HLm = 49 m
- Airport Elevation = 1800 m
- HLcor = 52.12 m

规范中 D 类高度损失为：
- 无线电高度表余度 26 m；
- 气压高度表余度 49 m。

机场高于 900 m 后，每 300 m 机场标高，气压高度表余度增加无线电高度表余度的 2%。

因此：

`49 + 26 × 0.02 × (1800 / 300) = 52.12 m`

与 B3 默认值完全一致。

这基本证明旧软件确实实现了该 HL 高海拔修正公式，而不只是存了几个经验值。

### 2.12 APV Z 面与 Xz

规范中 Z 面标称梯度为 2.5%，标准起点：
- CAT A/B：-900 m
- CAT C：-1100 m
- CAT D：-1400 m

机场较高或 VPA 大于 3.2°时还需要按 HL、RDH、ATT、TAS 等重新计算 Xz。

因此 `comboXz` 不应仅理解为三个固定下拉值。需要验证代码是否：
1. 只允许手动选择 -900/-1100/-1400；
2. 或者在高海拔/陡 VPA 情况下自动修正。

### 2.13 APV OCH 计算

规范把障碍物分成进近障碍物和复飞障碍物。

进近障碍物：
- 穿透 FAS 或地面平面时，障碍物高 + HL；
- 穿透侧面时，HL 从内侧全值向外侧线性减至 0。

复飞障碍物：
- 需要换算成当量进近障碍物高度 `ha`；
- 再加相应 HL；
- 最终 OCH 取最后进近 OCH 和复飞 OCH 中的较大值。

所以 B3 的障碍物评价至少包含：
- 面穿透判定；
- 主/副侧面折减；
- approach/missed 分类；
- missed obstacle equivalent height；
- HL；
- OCH 最大值选择。

### 2.14 B3 中仍需代码判定的字段

当前不能仅凭帮助和规范完全确定：

- `textBoxMDist`
- `textBoxMStart`
- `textBoxMEnd`
- `textBoxMPdg`
- `textBoxMCG`
- `tbSocToTp`
- `tbThrToSoc`
- `textBoxTpAlti`
- `comboBoxHi`

它们显然与复飞长度、SOC、TP、复飞梯度、APV 面分段有关，但每个字段具体对应哪条几何边界，应由代码恢复。

## 3. B4 PBN-ILS

### 3.1 功能定位

帮助文件的标题不是一般的“ILS OAS”，而是：

`B4.PBN-ILS 定点转弯评估`

命令：

`Y54_PBN_ILS`

帮助描述：
- 基于 OAS 面参数；
- 评估 PBN-ILS 定点转弯区障碍物穿透；
- HL 修正检查；
- CAD 绘制进近复飞评估面；
- KML 输出。

因此 B4 的重点不是纯 ILS OAS，而是 ILS 精密航段与 PBN 航段，特别是复飞转弯之间的衔接。

### 3.2 B4 与传统 OAS 模块存在明显继承/复制关系

B4 `config.xml` 暴露：
- FAF 高度；
- DH；
- 机场标高；
- 灯光长度；
- 复飞梯度；
- 翼展；
- 轮高；
- RDH；
- 航向台至入口距离；
- GP；
- 进近类型；
- W / W* / X / Y / Z 面 A、B、C；
- HL 检查。

这些字段与 `FormOasEvl` / A5 精密进近 OAS 数据高度重合。

因此 B4 很可能直接复用了传统 ILS OAS 参数引擎。

逆向时应优先检查 B4 与：
- FormPA
- FormOasEvl
- OAS 数据库查询
- OAS 面高计算
- HL 修正

是否共用方法。

### 3.3 OAS 参数本身的规范意义

规范中 ILS OAS：
- 以跑道入口为原点建立 x/y/z 坐标系；
- x 轴沿精密航段；
- y 在计算时取正值；
- OAS 由 W、W*、X、Y、Z 等斜面和入口水平面构成；
- 各斜面使用 `z = A x + B y + C`；
- 对给定障碍物，应计算各适用面的面高并取最高值；
- 系数取决于 GP、航向台至入口距离、运行类别、航空器尺寸、RDH 和复飞梯度等。

这与 B4 中大量 A/B/C 系数字段完全一致。

### 3.4 oas.db 的可能角色

当前数据库：
- PartA：275 行
- PartB：687775 行

样例 OAS 参数文件包含：
- AppType
- CAT
- GP
- FAF
- ELEV
- LIGHT
- W/WS/X/Y/Z 的 A/B/C

这与 B4、A5 的 OAS 字段高度吻合。

因此 oas.db 很可能存储 PANS-OPS OAS 软件参数表或其压缩/编码形式。

但在尚未解析数据库键值轴之前，不能直接把 PartA/PartB 某一维解释成 GP、LOC 距离或航空器类别。必须由代码查询路径证明。

### 3.5 Misc 中 RNAV-ILS 课程资料的重要性

`1-RNAV ILS 2017.pdf` 和 `2-RNAV+ILS(Day3).pdf` 明确讲授了：

- RNAV/RNP 初始航段连接 ILS；
- RNAV 中间航段与 ILS 精密航段连接；
- ILS 精密航段连接 RNAV/RNP 复飞；
- 指定 TP 转弯；
- 指定高度转弯；
- OAS 穿透障碍物评价；
- RNAV 主区/副区与 OAS Y/Z 面的组合评价。

这些内容与 B4 功能名称高度吻合，极可能是旧软件开发时的直接业务背景。

### 3.6 RNAV 到 ILS 的中间航段连接

历史课程资料明确说明：
- RNAV 模式在 IF 转换到 ILS 模式；
- IF 位于 LOC 轴线上；
- IF 是 Fly-by 航路点；
- 最大转弯角 90°；
- 中间航段必须足够长，使航空器先截获 LOC，再截获下滑道。

中间区的横向衔接是：
- IF 端采用 RNAV 初始航段末端的半宽；
- FAP 端采用 ILS OAS X 面扩展宽度；
- 两者之间形成中间进近保护区。

这与“保护区衔接”研究高度相关。

B4 是否实现了这一段，代码需要确认。帮助只说“进近复飞评估面”，没有详细列出 IF，因此不能仅靠课程资料认为 B4 已全部实现。

### 3.7 ILS 到 RNAV/RNP 复飞的几何

历史课程资料中，一条典型的 PBN-ILS 复飞构造为：

1. 从 TP 或指定高度位置建立 RNAV/RNP 复飞保护区；
2. 将 ILS Z 面继续向后延伸；
3. 找到 Z 面到达 RNAV/RNP 主区的位置 E′；
4. 从 SOC 位置用 15°扩张，使 ILS/OAS 的 Y 区逐步连接到 RNAV/RNP 区；
5. 直到最早 TP 或指定高度转弯位置，按组合后的主/副区进行障碍物评价；
6. 转弯后转入一般 PBN 转弯保护和障碍物评价。

这解释了为什么 B4 需要 OAS 参数，但又被称为“PBN-ILS 定点转弯评估”。

### 3.8 B4 很可能不是通用 PBN 参数化工具

值得注意的是，B4 的 `config.xml` 中没有明显的：
- ATT
- XTT
- SW1/SW2
- RNP 值
- Fly-by/Fly-over 类型选择

这与 B1/B2 完全不同。

而课程资料中的 RNAV-ILS 示例大量使用：
- RNP APCH / RNP1 / RNAV1
- 复飞 1/2AW = 2 NM
- 15°扩张

因此一个较强但尚未代码证明的判断是：

B4 可能把 RNAV/RNP 复飞的某些 PBN 宽度和容差规则固定在代码中，而不是让用户输入。

这也是后续必须重点检查的问题，因为如果确实如此，新系统不能照搬这种硬编码设计。

### 3.9 B4 的障碍物评价分区可能很复杂

历史课程资料显示，PBN-ILS 组合复飞的障碍物评价至少分为：

- E′之前：按传统 ILS OAS 方法；
- E′至最早 TP：
  - RNAV 主区内仍基于 Z 面；
  - RNAV 副区内需要判断 Y/Y延伸/Z 穿透；
  - 障碍物高还要扣除一个从一定值线性变化的 M；
- 最早 TP 之后：
  - 转入 PBN 转弯区；
  - 大于 15°转弯使用 50 m MOC；
  - 小转弯使用 30 m；
  - 副区 MOC 线性减小。

如果 B4 实现的是课程中的这套算法，那么其真正难点不在 OAS 面方程，而在：
- E′ / E″等控制位置；
- OAS 与 RNAV 主副区的空间叠加；
- 不同区段的障碍物分类；
- MOC/高度折减；
- 当量进近障碍物高度；
- HL；
- OCH。

### 3.10 B4 定点转弯的含义需要代码确认

帮助明确叫“定点转弯评估”。

但配置文件中没有明显 TP、ATT、转弯角度等输入项。

可能存在几种情况：
1. TP/转弯几何通过 CAD 拾取获得；
2. 程序采用固定的示例/默认 PBN 几何；
3. 部分参数存放在配置中未被当前字段名直接识别；
4. B4 实际只做障碍物评估，保护区几何由其他命令先生成。

这一项不能靠规范强行补全，必须作为后续代码和 AutoCAD 运行验证重点。

### 3.11 KML 输出的研究价值

B4 是少数帮助中明确提供 KML 输出的模块。

这可能暴露：
- 内部保护区边界的数据结构；
- 局部 CAD 坐标到地理坐标的转换；
- OAS / PBN 复飞面在导出前的几何分组；
- 各面名称和区域标识。

逆向时 KML 导出函数可能比 CAD 绘图函数更容易得到完整的几何顶点和面分类，应作为 B4 的优先代码入口之一。

### B4

`A5 / FormOasEvl`
→ ILS OAS 参数和面高计算

`oas.db`
→ OAS 系数来源

`B1/B2`
→ PBN 转弯几何的潜在复用

`A9`

## 6. 当前不应提前下结论的事项

不能因为课程资料中出现某一规则，就直接断言 B4 已实现。

尤其以下内容仍需代码证明：
- B4 是否实现 RNAV→ILS 中间段；
- B4 是否同时支持 Fly-by 和 Fly-over；
- 是否只支持指定 TP 转弯；
- 是否支持指定高度转弯；
- PBN 半宽是否固定 2 NM；
- E′/E″是否真实存在于代码；
- B4 是否真正调用 oas.db，还是仅使用用户输入系数。

规范和历史课程资料现在已经足以解释这些概念的业务意义。后续 Codex 的任务只需回答“旧软件有没有这样实现、在哪里实现、实现细节是什么”。
