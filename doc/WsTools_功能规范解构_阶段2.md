# WsTools 功能—规范—算法解构（阶段 2）

范围：A6 传统保护区模板、A9 主副区评估、A8 复飞转弯区评估、A7 离场越障评估。规范基线：AC-97-FS-005（2020）。本文件只给出帮助文件与规范能够支持的业务解释；旧软件实际实现仍以 DLL/IL/运行结果为准。

## 1. 这一阶段的主要修正

A7 与 A8 不能简单理解为两套相似的“转弯区绘图器”。A7 帮助中明确存在 CAD 绘制保护区；A8 帮助中没有 CAD 绘制按钮，而是输入 KK′ 左/右端点、Ds、MOC、梯度后对屏幕障碍物进行一键评估。因此目前更合理的假设是：A7 负责离场保护区构造与评估，A8 更偏向在已确定的复飞转弯区内进行障碍物越障计算。是否存在隐藏的几何构造仍需代码确认。

A6 则不是普通“绘图模板集合”。其帮助参数、默认值和规范附录 C 的模板描绘法高度一致，极可能是对传统反向程序/等待程序模板算法的直接实现。A6 应作为恢复传统程序保护区几何原语的重要入口。

## 2. A6 传统保护区模板

### 2.1 公共转弯参数的规范含义

帮助默认参数：IAS 380 km/h、高度 900 m、坡度 25°、ISA 温差 15℃、风速 97.8 km/h。

其中 97.8 km/h 不是任意默认值，而与规范传统反向/等待程序采用的 ICAO 全向风公式完全吻合：

`w = 12 h + 87 (km/h)`，h 以 km 计。

900 m = 0.9 km，因此 w = 12×0.9+87 = 97.8 km/h。

规范同时规定传统反向程序平均达到的坡度取 25°或 3°/s 转弯率对应坡度的较小值；TAS 大于 315 km/h 时使用 25°。这与 A6 默认坡度 25°和“自动计算 ICAO 标准风”的帮助说明相互印证。

这说明 WindSpiral/A6 中的通用 TurnParameterControl 很可能是一个“参数化转弯几何引擎”，业务模块再向它传入不同飞行阶段的风、坡度、速度规则。离场 A7 使用 15°和 56 km/h，不应与 A6 的 25°/ICAO 高度风混为一套默认规则。

### 2.2 基线转弯

帮助暴露：左右入航、按距离/按时间、VOR/NDB、天线高度、主区 MOC、副区宽度，以及 CAD 绘制。

规范附录 C 的模板描绘法表明，基线转弯主区模板综合了导航设施容差、飞行技术容差和风影响。其构造不是单一圆弧，而包括：

- 标称程序轴、出航航迹、入航转弯；
- VOR/NDB 出航保护线；
- 若干以无风转弯半径 r 构造的圆弧；
- 每个关键点对应的风影响圆弧；
- 多组圆弧螺旋包线；
- 包线之间的公切线；
- 加入保护和副区。

因此 A6 中的“辅助风螺旋线”和 WindSpiral A1 的单/双/三螺旋、公切线很可能有直接代码复用关系。这里应优先查公共“圆弧包络/公切线”几何函数，而不是只找 FormTemplate 自己的事件。

帮助允许基线转弯按距离或按时间定义出航。规范也允许出航航迹用计时、径向线或 DME 距离限制；若按时间，基线转弯出航/入航夹角 φ 还随 TAS 和时间变化。因此 Codex 后续需验证“按距离”模式是否真正实现规范的距离限制几何，还是只把用户输入距离直接当作模板长度。

### 2.3 45°/180°程序转弯

规范给出的标称结构为：有航迹引导直线出航 → 45°转弯 → 无航迹引导计时直线 → 反向 180°转弯切加入航。模板构造还要叠加 ±5°航向容差、转弯时间、风影响圆弧、圆弧螺旋包线和公切线。

帮助中的【包络线】要求用户选择已绘制的多个模板多段线后生成包络保护区，这一点很重要：旧软件至少有一部分“多情景包络”没有内部自动完成，而是让设计人员先生成多个候选模板，再人工选择后做几何并集/外包络。后续自动化系统应把这一人工步骤识别为可自动化候选。

### 2.4 80°/260°程序转弯

规范明确 80°/260°程序由 80°出航转弯和反向 260°入航转弯组成。模板需要考虑 75°/85°的飞行技术容差位置、若干 45°/90°/135°/180°等关键转角点、风影响圆弧及螺旋包线。

帮助说“80°/260°程序转弯的出航时间由80°几何关系确定，无需单独输入”。这一点不能理解为规范没有时间因素；更可能是软件内部按模板几何和速度自动推导相关飞行时间。代码应验证实际公式来源。

### 2.5 等待与直角航线

帮助把等待和直角航线放在同一页，并提供【全向等待】【XE】【YE】【等待模板】。规范附录 C 说明两者的基本保护区结构相同，但直角航线外围是主区+副区，而等待程序是基本保护区+缓冲区；模板原点还需要沿导航定位容差区移动以形成最终保护区。

因此 A6 “等待与直角航线”至少包含三个不同层次：模板本身、定位容差扫掠后的基本保护区、加入区域/缓冲区。不能只恢复一个“holding polygon”函数就算完成。

## 3. A9 主副区评估

帮助把 A9 定位为某一直线航段的主/副区与 OCA 评估。config.xml 暴露了两个宽度和两个 MOC：`Width1/Width2`、`MOC1/MOC2`，说明该工具并非只能处理等宽、等 MOC 的简单矩形航段，至少允许起止位置参数不同。

规范一般准则给出两条基础关系：

1. 两定位点之间副区宽度可以沿航迹线性插值；
2. 在任一横截面，副区 MOC 从主区边界的全值线性减小到副区外侧边界的 0。

因此 A9 的预期算法很可能是二维双重插值：先根据障碍物沿航迹位置得到该截面的保护区宽度/MOC，再根据横向位置判断主区/副区并计算副区折减 MOC。

但帮助中“起点/终点坐标定义 kk' 线的两端坐标”的文字存在歧义，不能据此断言这两个点一定是航段中心线端点。代码需要确认：

- 两个坐标点到底定义航段轴线、KK′截线还是评估基准线；
- Width1/Width2 分别作用于哪两个纵向位置；
- MOC1/MOC2 是否也沿纵向插值；
- `checkBoxPA`（精密中间段）开启后修改的是区域几何、MOC 还是 OCA 计算方式。

A9 应优先恢复成独立的 `EvaluatePrimarySecondaryObstacle(...)` 类函数，因为它很可能是后续多个程序模块的共同评价原语。

## 4. A8 复飞转弯区评估

### 4.1 功能定位修正

帮助没有列出 CAD 绘制按钮，只列出 KK′ 左/右端点、转弯方式、PDG、Ds（SOC 至转弯最早点）、MOC、复飞梯度、障碍物载入和一键评估。

因此当前最可信的功能定位是：A8 主要解决“转弯区内障碍物允许高/OCA 的计算”，而不一定负责转弯边界几何生成。真正的转弯区边界可能已经由其他功能画好，设计人员再把需要评估的障碍物通过“屏幕数据”送入 A8。

### 4.2 KK′、Ds 与规范关系

规范在指定 TP 转弯复飞中使用最早 TP、最晚 TP 以及 K/KK 类边界；外侧边界从最晚 TP 定位容差开始，内侧边界由最早 TP 所在位置控制。复飞/精密进近的障碍物公式中也经常出现从 SOC 至最早 TP 的距离 dZ/Ds，以及障碍物至 KK′线的最短距离 dO。

因此帮助中的 Ds 很可能是把规范公式中的 `SOC → 最早TP` 水平距离直接暴露给用户；KK′ 左右端点则用来计算障碍物到 KK′线的最短距离。

这意味着 A8 代码最值得寻找的不是 Polyline 创建，而是：

`point-to-line distance → dO = Ds +/or obstacle-to-KK → climb surface height → MOC deduction → obstacle result/OCA`

不同“转弯方式”选项卡可能选择不同的距离定义和 MOC 公式。只有代码才能确定实际分支。

### 4.3 与 A7 的关系

规范明确规定传统离场转弯区采用转弯复飞保护区相同的设计方法，但这不等于 A7 与 A8 必然共用同一个“绘图方法”。更可能的复用有两类：

- A7 的几何构造调用一般转弯保护区算法；
- A8 的障碍物评价公式与 A7 的转弯区越障评价共享距离/MOC 计算。

后续代码验证应分别检查“几何复用”和“评价复用”，不能只查 Form 之间是否互相调用。

## 5. A7 离场越障评估

A7 是当前最重要的完整业务模块。帮助中三个选项卡对应三套不同规范逻辑，而不是同一函数换几个参数。

### 5.1 共同前置数据

跑道数据给出 DER/THR 坐标和标高。真正的局部坐标应以跑道轴线确定，DER 是离场纵向计算的主要参考点。帮助提供“入口坐标系”转换，说明旧软件当前仍依赖设计人员先建立/转换 CAD 坐标，而没有统一的机场/跑道数据模型。

障碍物通过【屏幕数据】从 CAD 点实体导入，说明障碍物空间筛选在很大程度上仍依赖当前图面中的对象集合，而不是软件内部的障碍物数据库查询。

### 5.2 定高转弯

帮助默认：PDG 3.3%、转弯高度 300 m、KK′-DER = 8939.39 m、IAS 380、坡度 15°、温度 15℃、风 56 km/h。

这里有一个重要的帮助文字修正：在“指定高度转弯”中，KK′-DER 默认 8939.39 m 恰好等于：

`(300 - 5) / 0.033 = 8939.39 m`

因此这个选项卡中的 KK′/K-K 并不是“TP 定位容差最早点”。指定高度转弯的 TP 本来就不是定位点，而是按 PDG 爬升至指定高度的计算位置。规范称标志转弯起始区结束的线为 KK 线。帮助把它解释成“定位容差最早点”容易造成业务混淆，应以规范和代码为准。

预期计算链：

1. `dr = (TNA - DER_elev - 5)/PDG`；
2. 在跑道航迹上确定 TP/K-K 位置；
3. 转弯起始区按直线离场规则延伸至 K-K；
4. 转弯参数使用转弯高度、IAS→TAS、15°坡度、56 km/h（或统计 95% 风）；
5. 内侧边界：根据转弯角 <75° 或 ≥75°选择起始侧，然后相对转弯后标称航迹按 15°扩张；
6. 外侧边界：在转弯起始区外侧边界加飞行技术容差 c 得 A 点，从 A 点按一般转弯保护区的风螺旋/边界圆规则绘制；
7. 评价转弯起始区和转弯区障碍物。

其中第 5 步需要知道“转弯后的标称航迹”，帮助页没有显式参数，但 config.xml 中存在 `textBoxTurnEndX/Y` 和一个 comboBox，说明 CAD 运行中很可能还要拾取转弯终点/方向。帮助文件对此记录不足，必须由代码/运行行为补齐。

### 5.3 `DER之前转弯` 复选框

规范默认需要考虑固定翼飞机可能在 DER 之前转弯，因此转弯起始区从跑道起始端 600 m 处开始；只有当程序明确禁止 DER 之前转弯时，转弯起始区才从 DER 开始。

帮助把该复选框写成“勾选后按在 DER 之前开始转弯的模式计算”。这与规范逻辑一致，但代码仍需确认布尔值的正反意义，特别是默认值为 False 时旧软件究竟采用哪一种保护。

### 5.4 定点转弯

帮助输入：TP- DER、最早TP、最晚TP、参考高度、计算高度，以及 IAS/坡度/温度/风。

这里必须区分两个“高度”：

- 参考高度 = `TP距离 × 实际PDG + DER标高 + 5`，用于显示按离场程序设计梯度到达 TP 时的理论高度；
- 计算高度 = `TP距离 × 10% + DER标高 + 5`，是规范允许用于“指定 TP 转弯参数计算”的保守高度，用于 IAS→TAS、风、转弯半径等参数确定，而不是实际要求航空器按 10% PDG 飞行。

规范规定指定 TP 时直线离场准则使用至最早 TP。TP 的最晚限制由定位容差和飞行技术容差 c 共同形成；若 TP 由 DME 定义，还有 23°夹角限制。外侧边界从最晚 TP 容差开始，沿风螺旋/边界圆至切线与后续标称航迹平行；内侧主/副区与下一航段保护区连接时存在 A/2 收敛和 15°扩张两种条件分支。

因此帮助中的：

- `最早TP = KK′至TP距离`
- `最晚TP = C至TP距离`

应该理解为旧软件把名义 TP 与纵向早/晚限制之间的距离直接暴露给用户。`C` 在这里很可能是“最晚位置”相关构造，但其符号方向、是否已经包含 c、是否与定位容差分别存储，需要代码确认，不能只靠名称判断。

### 5.5 直线段二次检查

规范明确：指定 TP 转弯时，直线离场准则要一直使用到最早 TP。因而帮助中的“直线段二次检查”很可能用于再次按直线离场保护区/OIS 对最早 TP 以前的障碍物做筛查，避免只按转弯区公式评价后漏掉直线段控制障碍物。

这是一个强业务推断，但仍需代码确认其具体评估区域、梯度和 MOC。

### 5.6 全向离场

帮助只暴露三个主要参数：PDG、转弯高度 TNA、终点高度。

规范中的完整全向离场实际上包含三类区域：

- 第1区：按 PDG 从 DER 爬升至最低转弯高 120 m；
- 第2区：之后按与离场航迹 30°向外扩张，直到规定的更高转弯高度；
- 第3区：覆盖任意方向大于 15°转弯，范围与按 PDG 爬升至下一巡航高度或 MSA 所需距离有关。

此外，完整规范允许按扇区设置不同转弯高度、PDG 或禁止扇区。

旧软件全向离场界面没有扇区方位、各扇区 PDG/TNA、MSA 或禁飞扇区输入，因此它大概率只实现“统一 PDG + 统一 TNA + 单一终点高度”的基本全向保护区，而没有完整的扇区化全向离场设计能力。代码需要确认终点高度是否被直接换算为第3区半径，以及圆心到底取跑道起始端+600 m、DER 或其他点。

这是旧软件功能边界的重要结论：恢复旧代码时应忠实恢复现有简化实现，后续新系统再按规范补全扇区化能力。

## 6. A7 中保护区衔接应优先恢复的几何节点

后续不需要把整个 Y07 一次性反编译。按以下节点逐个“破甲”更有效：

### 指定高度转弯

`TNA/PDG → TP(K-K) → turn-start-area boundary → A = outer boundary + c → wind spiral → tangent P → post-turn boundary`

同时追：

`turn angle <75° ? inner-side-start : outer-side-start → 15° expansion → post-turn protection`

### 指定点转弯

`nominal TP + fix tolerance → earliest K-K / latest limit (+c) → A → wind spiral → tangent P`

内侧：

`K-K → connection point with next segment → outside next area ? converge A/2 : diverge 15°`

### 障碍物评价

至少分开验证：

- 转弯起始区；
- 转弯区；
- 直线段至最早 TP；
- 主区/副区 MOC 折减（如果该离场分支存在副区）；
- 控制障碍物与要求 PDG。

## 7. 现在可以缩减给 Codex 的第二批问题

在阶段 1 的基础上，下一次 Codex 不应接收“完整逆向 A6-A9”这种开放任务，只需要回答以下确定问题：

1. **A6 公共几何**：定位并恢复圆弧螺旋包线、公切线、模板扫掠/包络线三个公共几何操作；证明哪些被基线、45/180、80/260、等待共同调用。
2. **A6 参数**：确认 `97.8` 是否由 `12h+87` 实时计算，25°/3°s 限制是否代码化，还是 UI 默认值而已。
3. **A9**：恢复 Width1/Width2、MOC1/MOC2 的纵向/横向插值关系，明确两个坐标点的几何意义。
4. **A8**：先不要找保护区绘图，直接从“一键评估”事件反向追障碍物公式，确认 KK′、Ds、MOC、复飞梯度各自怎样进入计算，并列出不同转弯方式分支。
5. **A7 定高**：只恢复 `dr/TNA → K-K → A点 → 内外侧边界 → CAD实体` 这一条链；确认 turnEndX/Y 的用户交互含义。
6. **A7 定点**：恢复 TP、KK2Tp、C2Tp 的方向和组成，确认 C 是否包含飞行技术容差 c；恢复“直线段二次检查”的真实区域与公式。
7. **A7 全向**：确认旧实现是否只实现统一三区域模型；恢复第1/2/3区中心、半径、30°扩张和终点高度到半径的换算。
8. **共享评价**：确认 A7/A8/A9 是否调用同一障碍物距离、MOC、副区折减函数；若没有共享，记录重复实现。
