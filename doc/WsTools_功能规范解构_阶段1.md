# WsTools 功能—规范—算法解构（阶段 1）

范围：`WindSpiral2026/帮助文件` 中 A2 基础计算、A1 风螺旋、A3 定位容差，并向 A9 主副区、A8 复飞转弯区、A7 离场延伸。规范基线：AC-97-FS-005（2020）。

## 1. 当前逆向分工

本阶段不要求 Codex 自主理解飞行程序设计。先由业务/规范层把每个功能的设计含义、应有条件分支和预期算法解释清楚，再由 Codex 定点恢复实际实现。

判断原则：

- 帮助文件说明旧软件向设计人员暴露了什么功能、参数和 CAD 操作。
- 规范说明这些参数在飞行程序设计中的业务含义和应有算法。
- DLL/IL/运行行为决定旧软件实际上怎样实现。规范不能替代代码证据。
- 帮助与现行规范不一致时保留差异，交由代码判断旧实现采用的规则或版本。

## 2. A2 飞行程序基础计算

帮助文件把 A2 划分为六个独立计算器：FAF、非精密 SOC、精密 SOC、复飞 TP、离场 TP、C 容差。它不是一个完整程序设计模块，而是后续几何功能复用的基础计算集合。

### 2.1 FAF 计算

帮助给出的关系：

`FAF-THR = (FAF高度 - RDH - THR标高) / tan(GP)`。

业务含义是利用最后进近垂直几何关系反求 FAF 至入口的水平距离。Codex 只需确认单位、角度制、结果绘图方向以及中间段长度是否参与最终绘图。

### 2.2 非精密 SOC

帮助默认以 IAS、高度、温度和风换算 TAS，使用 18 s 得到距离。

现行规范把 SOC 分为 MAPt 容差和过渡距离两部分。MAPt 由导航台/定位点定义时，飞行员反应距离按 3 s 计算；过渡距离 X 按 TAS 飞行 15 s 计算。因此帮助中的 18 s 很可能是把 3 s 反应距离和 15 s 过渡距离合并为一个辅助计算，但帮助文字“MAPt 定位容差最晚点与 SOC 之间 18 s”并不严谨。

代码需要确认：18 s 是固定常量还是 3+15 两部分；计算起点究竟是标称 MAPt、定位容差边界还是已经加上反应距离后的最晚边界。

### 2.3 精密 SOC

帮助使用 GP、Xz、DH、机场标高、机型、HLm、HLr 和 HL 修正，并给出 `SOC高 = DH - HL修正`、`THR-SOC = (DH-HL修正)/tan(GP)+Xz`。

现行规范明确存在高度损失/高度表余度 HL，对机场标高大于 900 m 的情况需要按无线电高度表余度进行增量修正；大下滑角还存在额外修正。旧软件帮助仅展示部分规则，不能直接认定为现行完整实现。

代码需要确认：机型到 HLm/HLr 的表值来源；Xz 的选取逻辑；标高修正和 GP>3.2°修正是否都实现；该页对应的是哪一版 ILS/OAS 精密进近规则。

### 2.4 复飞 TP

帮助公式：

`SOC-TP = (转弯高度 - SOC高度) / 复飞梯度 × 100`。

这是沿复飞爬升梯度反求达到转弯高度所需水平距离的辅助计算。后续应与 A8 转弯复飞的最早/最晚 TP 和 KK′ 关系联合解释。

### 2.5 离场 TP

帮助公式：

`DER-TP = (转弯高度 - DER高度 - 5) / PDG × 100`。

现行规范规定离场转弯高度/高满足 `TNH = dr × PDG + 5 m`，因此该计算正是其反解。这里的 5 m 是 PDG 在 DER 上方 5 m 起算造成的，不是经验修正量。

### 2.6 C 容差

帮助默认 6 s，并计算 `(TAS + 风速) × 6 / 3.6`。

现行规范对传统离场指定转弯点明确把飞行技术误差 c 定义为指定速度飞行 6 s 的距离，其中包括 3 s 飞行员反应时间和 3 s 建立坡度时间。无统计风资料时离场采用 56 km/h（30 kt）全向风。

代码需要确认：风值是否可以由统计风替换；IAS→TAS 换算是否直接复用公共 TurnParameterControl；单位切换后的 6 s 距离是否一致。

## 3. A1 风螺旋

帮助暴露 IAS、高度、坡度、风速、ISA 温度偏差、左右转、起止角、偏置以及单/双/三螺旋、公切线、标称航迹等绘图功能。

规范层能够直接确定的计算链为：

`IAS + 高度 + 温度 → TAS → 转弯率 R → 无风转弯半径 r → 风影响 Eθ → 风螺旋离散点 → 边界曲线`。

规范给出：

- `R = (6355 tan α)/(πV)`（V 为 km/h），最大 3°/s；
- `r = V/(20πR)`；
- `Eθ = (θ/R) × w/3600`；
- 风螺旋可按例如 30°间隔逐点构造，减小角度间隔提高精度；
- 外侧保护区在 P 点达到与转弯后标称航迹平行的切线条件。

因此 Codex 不需要猜三角函数的意义，只需定位这些量在旧代码中的实际实现。

仍需代码解释的部分主要是“单螺旋、双螺旋、三螺旋”的软件特有语义：它们是否分别对应一个起始边界、两个不确定起始位置或多个包络构造；公切线如何选择；PLine/Spline 两种输出是否只是 CAD 表示差异；起止角和 InitOffset 如何影响局部坐标系。

## 4. A3 定位容差

帮助把 A3 分为交叉定位和顶空盲区，并暴露 VOR/NDB/DME 等设备、设备精度、DME 距离、航迹引导、航迹线、KK 线和航迹容差等绘制选项。

规范明确：定位容差区由航迹引导和沿航迹径向线/距离弧的系统精度边界围成；定位容差是标称航迹与容差区最早/最晚限制的交点到标称定位点的沿航迹距离。交叉定位的系统使用精度来自相关误差的 RSS。DME 精度为 ±[0.46 km（0.25 NM）+ 距离的 1.25%]。VOR 顶空定位基于半角 50°的倒圆锥盲区。

因此 A3 的真正输出至少应区分：二维定位容差区、沿航迹早/晚容差、可能的 KK 类限制线、导航台顶空盲区。

代码需要确认：不同设备类型内置的角度精度表；交叉两台设备与 VOR/DME 同台两种几何是否分支；“航迹引导”复选框改变的是 2σ/3σ、保护区扩张还是仅绘图；KK 线在 A3 中的精确定义以及是否直接供 A7/A8 使用。

## 5. A9、A8、A7 已形成的依赖关系

### A9 主副区

帮助定位为“某一直线航段”的主区/副区和 OCA 评价。规范规定主区提供全 MOC，副区 MOC 从主区边界线性减小至外侧边界为零：

`MOC_secondary = MOC_primary × (1 - Y/WS)`。

这说明 A9 很可能是障碍物评估公共原语，而不是单纯绘图窗体。后续需要查它是否被 A7/A8/A4 等直接调用，还是这些模块各自复制了同类代码。

### A8 复飞转弯区

帮助输入 KK′ 左/右边界、转弯方式、PDG、Ds、MOC、复飞梯度并执行障碍物评价。规范规定转弯复飞可以在指定高度、定位点/电台或 MAPt 开始；指定点转弯保护区从 TP 容差最晚边界建立外侧边界，内侧边界则依赖最早点和直线复飞边界。

传统离场规范又明确引用“转弯复飞保护区”的设计方法，因此 A8 与 A7 的关系不是偶然相似，而应重点检查是否共享几何算法或障碍物评价算法。

### A7 离场

帮助已经清楚暴露三个业务分支：定高转弯、定点转弯、全向离场。

定高转弯输入 KK′-DER、转弯高度、IAS、坡度、温度、风；定点转弯额外使用 TP、最早 TP、最晚 TP、参考高度、按 10% 梯度得到的计算高度；全向离场使用 PDG、TNA 和终点高度。

规范可以解释其中大部分含义：

- 指定高度和指定 TP 是两类不同离场算法；
- 指定 TP 时，最早限制为 K 线，最晚限制由 K 线、TP 定位容差和飞行技术容差 c 共同决定；
- 指定 TP 的转弯高度计算使用从 DER 到 TP 的 10% 爬升梯度，这与帮助中的“计算高度 = TP距离×10% + DER标高 + 5”一致；
- 外侧边界从最晚 TP 容差开始，沿风螺旋或边界圆直到切线与转弯后标称航迹平行；
- 内侧主/副区与下一航段衔接存在 A/2 收敛与 15°扩张两种条件分支；
- 转弯离场的转弯保护区方法引用转弯复飞方法，因此 A7/A8 应重点寻找共享实现。

## 6. 现在交给 Codex 的问题应该缩小为代码验证

第一批只需回答以下问题，不再要求泛化“逆向这些模块”：

1. A2：定位六个计算器的计算事件和公共 TAS 换算函数，逐一输出公式、token/RVA 和等价 C#。重点解释非精密 SOC 的 18 s 究竟如何组成。
2. A1：定位 R、r、Eθ 和风螺旋离散点的实际方法；恢复单/双/三螺旋及公切线的具体几何语义。
3. A3：恢复 VOR/NDB/DME 交叉定位、顶空盲区、早/晚容差和 KK 线的具体算法及内置精度数据。
4. A7/A8 暂时只做调用关系验证：查明二者是否复用同一转弯边界/风螺旋/障碍物评价方法，不急于完整恢复离场。
5. A9：确认主副区 MOC 线性递减是否存在公共实现，以及哪些模块调用它。

完成这五项后，再进入 A7 定高和定点转弯的完整功能恢复。
