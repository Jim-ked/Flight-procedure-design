# WsTools 功能—规范—算法解构（阶段 3）

范围：B1 旁切转弯（Fly-by）、B2 飞越转弯（Fly-over DF）、B5 PBN 离场。规范基线：AC-97-FS-005（2020）。本阶段继续以“帮助文件说明软件暴露功能，规范解释业务语义，旧 DLL/运行行为验证实际实现”为原则，不用规范替代代码事实。

## 1. 本阶段最重要的认识

B1、B2 并不是完整的 PBN 程序设计器，更接近“给定规范参数后生成转弯保护几何”的工具。帮助文件要求用户直接填写 IAS、高度、坡度、风速、ATT、航段宽度以及反应/建坡时间，说明旧软件没有把“飞行阶段 → 规范参数选择”完全封装起来。

这一点很重要。现行规范中离场、IAF/IF/FAF、复飞等阶段的坡度、风、飞行员反应时间、建立坡度时间并不相同。旧软件的独立 B1/B2 窗口把这些参数暴露出来，意味着设计人员必须先知道应该采用哪组规范参数，软件才负责后续的转弯点、风螺旋和保护区几何。

因此后续恢复源码时，应把以下两层严格分开：

1. 参数选择规则，即某类程序、某飞行阶段应采用哪些 IAS、高度、风、坡度、反应时间、建坡时间、ATT、半宽；
2. 几何构造算法，即给定上述参数后如何求最早/最晚转弯点、风螺旋、主副区和衔接边界。

新一代自动化系统以后应把第 1 层也自动化，而旧 WsTools 很可能主要实现了第 2 层。

## 2. B1 旁切转弯（Y51_FlyBy）

### 2.1 帮助文件暴露的功能

帮助明确说明 B1 用于绘制 PBN 旁切转弯保护区。用户填写：

- 转弯参数：IAS、高度、坡度、风速等；
- 前后航段数据：航迹和宽度；
- ATT；
- 反应时间、建立坡度延迟；
- 是否绘制标称航迹、定位容差、主区、副区、NN′、KK′、风螺旋等。

CAD 操作要求依次指定转弯起点、转弯点、转弯终点。

config.xml 中 B1 默认值为：

- IAS = 380 km/h；
- 高度 = 900 m；
- 坡度 = 25°；
- 风速 = 97.8 km/h；
- ATT = 1482 m；
- SW1 = SW2 = 4630 m；
- 反应时间 = 6 s；
- 建立坡度延迟 = 5 s。

1482 m = 0.8 NM，与规范 RNP 1 的 ATT 完全一致；4630 m = 2.5 NM，与固定翼 RNP 1 在距 ARP 30 NM 内 STAR/SID 的保护区半宽一致。因此 SW1/SW2 极可能表示前、后航段的保护区半宽（或等价的航段半宽输入），而不是全宽。这个判断证据较强，但仍需代码确认字段进入几何计算时是否按半宽直接使用。

25°、97.8 km/h、6 s、5 s 则与 IAF/IF/FAF 类传统/RNAV 转弯参数高度吻合，而不是离场参数。这进一步说明 B1 是通用转弯几何窗口，默认值只代表一种常用场景，不能把默认值当成窗口固定业务规则。

### 2.2 旁切转弯的规范几何含义

旁切航路点的特点是航空器在到达航路点前已经开始转弯。规范给出的名义转弯起始距离为：

`d_turn = r × tan(A/2)`

其中 A 为航迹改变角，r 为转弯半径。

用于保护区的最早、最晚转弯限制还要叠加 ATT 和飞行技术时间：

- 最早点：航路点之前 `ATT + 转弯起始距离`；
- 最晚点：`转弯起始距离 - ATT - 飞行员反应距离`，如果结果为负，则最晚点落在航路点之后。

所以 B1 的 CAD 三点并不是直接决定保护区边界。三点首先确定前一标称航迹、航路点、后一标称航迹以及转弯角 A；随后结合转弯半径、ATT 和时间容差得到真正的早/晚转弯限制。

### 2.3 KK′ 与 NN′

帮助称 KK′为最早转弯线、NN′为最早下降线，这与规范完全对应。

KK′ 位于转弯最早点，垂直于入航航迹。对于离场/复飞障碍物评价，它还是转弯前直线段的终止基准线，障碍物距离从最早转弯位置开始测量。

NN′N″只在旁切转弯作为梯级下降定位点时具有特殊意义。NN′位于航路点之前一倍 ATT，并垂直于前一航段；另一段 N′N″与角平分线有关。也就是说，NN′并不是“另一个 KK′”，它服务于下降最早点/最低高度评估，二者业务目的不同。

因此 Codex 后续必须验证 B1 中 NN 与 KK 是两套独立构造，而不是同一个基准线换偏移量。

### 2.4 外侧保护区与前后航段宽度衔接

帮助文件写“若前后航段宽度不同时，通过风螺旋进行衔接”。这句话方向正确，但比规范实际规则简化得多。

风螺旋/边界圆方法下，规范要求外侧主区采用最不利风螺旋，最多可能涉及 3 条风螺旋。之后与下一航段的衔接至少存在两种条件：

- 风螺旋形成的主区落在下一航段主区以内时，用与下一航段标称航迹成 15°、且与风螺旋相切的直线连接；
- 风螺旋形成的主区落在下一航段主区以外时，用与下一航段标称航迹成 30°、且与风螺旋相切的直线连接。

旁切转弯还要考虑速度范围的额外外扩：

- A ≤ 90°时，由分别与入航、出航方向平行且与最大速度风螺旋相切的两条线确定扩张限制；
- A > 90°时，几何条件发生变化，其中一条限制线改为与入航航迹垂直。

因此后续代码审计不能只搜索“SW1 != SW2 时调用 WindSpiral”。真正需要恢复的是：

`多个候选风螺旋 → 最不利包络 → 判断相对下一航段位置 → 15°/30°切线衔接 → 速度范围附加限制`。

### 2.5 内侧边界

内侧主区/副区也有明确分支：

- 最早转弯点处的前一航段边界已经位于下一航段对应保护区内，则从最早点按相对下一航段 15°向外扩张；
- 若位于下一航段保护区外，则从最早点按 A/2 与下一航段连接。

这一规则和传统指定点转弯的 A/2 与 15°逻辑非常接近，说明旧代码很可能存在可复用的“转弯内侧衔接”几何函数，也可能是作者重复实现。Codex 需要用调用关系证明，不应仅根据规范认为一定复用。

### 2.6 B1 最值得代码验证的问题

1. SW1/SW2 是否直接表示 1/2AW；
2. ATT 是否仅作为沿航迹偏移，还是参与其他宽度/障碍物计算；
3. `r*tan(A/2)` 的最早/最晚两套转弯起始距离是否都实现；
4. ReactTime=6、BankAngleDelay=5 分别进入哪一个早/晚限制；
5. 最多 3 条风螺旋的“最不利包络”怎样实现；
6. 15°与30°外侧衔接条件是否完整；
7. ≤90°和>90°的速度范围附加扩张是否实现；
8. NN′与KK′是否真正进入障碍物评价，还是仅作为绘图辅助线。

## 3. B2 飞越转弯—DF（Y52_FlyOver）

### 3.1 功能范围要严格限定

帮助标题不是泛化的“飞越转弯”，而是“飞越转弯 - DF 航段”。这很关键。

PBN 规范中的飞越转弯可以接不同后续航段，但 B2 明确针对飞越航路点后接 DF（Direct to Fix）。因此不能把 B2 恢复成一个通用 Fly-over 类就认为完成；应保留“FlyOver + DF”这一业务限定。

### 3.2 飞越转弯的早/晚限制

规范表Ⅲ-2-2-1规定：

- 最早转弯点在航路点之前一倍 ATT；
- 最晚转弯点由 ATT、飞行员反应时间和建立坡度延时共同确定。

与旁切不同，飞越转弯没有 `r*tan(A/2)` 的提前转弯本质；航空器应先飞越航路点，再进入转弯过程。

config.xml 的 B2 默认值为：ATT 1482 m、SW 4630 m、反应时间 3 s、BankTime 3 s。ATT 和 SW 同样高度符合 RNP 1 的 0.8 NM ATT 与 2.5 NM 半宽。

但 B2 同时仍使用 25°、900 m、97.8 km/h 的公共转弯参数默认值，而 3 s+3 s 又与离场/复飞常用飞行技术时间相近。这个默认组合不是现行规范某一飞行阶段的完整自洽集合，至少不能仅靠默认值判定业务场景。需要把它理解为“用户可编辑的绘图初始值”。

### 3.3 DF 航段是 B2 的难点

DF 与固定出航 TF/CF 不同。规范对 DF 特别规定：

- 外侧最晚标称航迹应从下一航路点引出，并与最不利的主区风螺旋相切；
- 内侧最早标称航迹应从下一航路点连接到最受限制的早转弯点。

所以 B2 中用户在 CAD 图面拾取“转弯终点”很可能不仅用于确定一个普通出航航迹方向，而是定义 DF 的下一定位点。软件随后应根据该下一定位点和早/晚风螺旋自动形成一族可能航迹的包络。

这也是 B2 与 B1 在代码层最值得比较的地方：B1 有确定的后续标称航迹；B2-DF 的后续实际航迹是由下一定位点和转弯极限共同约束出来的。

### 3.4 “ATT=0 时与 PBN 定高转弯外边界相同”

帮助中特别注明：Fly Over 转弯 ATT=0 时，转弯外边界与 PBN 定高转弯保护区相同。

这个说明很可能泄露了旧软件内部结构：FlyOver-DF 与 PBN TA/H 可能共用同一个“从最晚纵向限制生成外侧风螺旋并接 DF”的几何函数，区别只在最晚限制的来源。

可以把代码搜索目标写成：

`latest longitudinal boundary → outer start point → worst wind spiral(s) → tangent from next fix / 15° or 30° connection`

然后比较 B2 与 B5 定高转弯是否进入同一方法。

注意，这只是由帮助文件给出的强线索。必须由调用图或等价 IL 证明实际共享，不能直接宣称源码一定复用。

### 3.5 B2 最值得代码验证的问题

1. CAD 中“转弯终点”是否就是 DF 下一航路点；
2. 最早、最晚点是否严格按 ATT 与反应/建坡时间形成；
3. DF 最晚标称航迹是否通过“下一定位点 → 最不利风螺旋切线”生成；
4. DF 最早标称航迹是否通过“下一定位点 → 最受限早转弯点”生成；
5. ATT=0 时是否真实调用 PBN TA/H 的同一外侧边界代码；
6. SW 是固定半宽还是可以根据前后定位点变化；
7. B2 是否只实现 DF，还是代码中还残留 TF/CF 隐藏分支。

## 4. B1 与 B2 的共享结构

config.xml 已经给出非常明显的共享证据：两者都包含同一个 `turnParameterControl1`，字段包括 IAS、高度、坡度、温度、风速。这说明至少 UI/参数层存在共享控件。

从规范看，两者的公共计算也很明显：

`IAS → TAS → 转弯率/半径 → 风影响 → 风螺旋 → 主副区边界`。

真正不同的是纵向转弯限制和后续航迹的构造：

- Fly-by：转弯起始距离与 `r*tan(A/2)` 有关，航空器在航路点前开始转弯；
- Fly-over：早/晚限制围绕航路点 ATT 及反应/建坡时间形成；
- Fly-over + DF：后续标称航迹还必须从下一定位点与早/晚转弯包络建立。

因此一个很合理的待验证代码结构是：

`CommonTurnParameters`
→ `BuildWindSpiral`
→ `BuildFlyByLongitudinalLimits` 或 `BuildFlyOverLongitudinalLimits`
→ `BuildTF/CFConnection` 或 `BuildDFConnection`
→ `BuildPrimarySecondaryBoundary`

但这是重构目标，不是当前已证明的原源码结构。

## 5. B5 PBN 离场（Y55_PBN_Departure）

### 5.1 软件暴露的范围比规范窄

规范中的 PBN 转弯离场允许四种转弯：

1. Fly-by；
2. Fly-over；
3. 指定高度/高（TA/H）；
4. RF。

而 B5 帮助只暴露两种：

- 定高转弯；
- 定点转弯（FlyOver-DF）。

因此至少从当前公开 UI 来看，B5 不是完整的 PBN 离场设计器。Fly-by 与 RF 没有作为 B5 的集成模式出现。

B1 可以单独生成 Fly-by 几何，但帮助没有说明 B1 的结果能够自动送入 B5 进行“一键离场障碍物评估”。因此不能把“B1存在”当成“B5完整支持 Fly-by 离场”。实际工作流是否需要人工组合多个窗口，必须由旧代码/实际使用经验确认。

### 5.2 B5 是一个组合功能，而不是新的独立几何体系

帮助中的按钮结构很有信息量：

- 转弯区评估；
- 直线段评估；
- 一键评估；
- CAD；
- 标记重要障碍物。

这说明 B5 很可能把三类能力拼接起来：

1. PBN 离场初始直线保护区；
2. PBN 转弯保护区（TA/H 或 FlyOver-DF）；
3. 障碍物评价与控制障碍物标记。

因此逆向 B5 时不应该寻找一个巨大的 `PbnDeparture()` 算法，而应该确认它调用/复制了哪些公共能力。

### 5.3 初始直线保护区

规范要求 PBN 离场初始保护区从 DER 向第一个航路点扩展，保护区宽度与导航传感器的 XTT、ATT 和 1/2AW 有关。保护区总宽度通过连接各定位点处不同的保护区宽度形成。

对于 RNP 1 固定翼飞机，规范给出了典型值：

- XTT = 1.0 NM；
- ATT = 0.8 NM；
- 1/2AW 随距离 ARP 的位置不同为 3.5、2.5 或 2.0 NM。

因此 B5 真正应该知道的不仅是一个固定“宽度”，还包括：

- 导航规范（RNP1/RNAV1 等）；
- 导航传感器；
- 距离 ARP/DER 的区段；
- 不同航路点处的半宽；
- 相邻半宽的扩张/收缩。

帮助页面没有暴露这些参数。这里产生两个可能：

A. B5 内部按某一固定 PBN 规范/默认值自动取值；
B. B5 实际实现比现行规范简化，只支持一种预设半宽。

这必须成为代码逆向的高优先级问题。

### 5.4 B5 定高转弯（TA/H）

PBN TA/H 离场不是传统 A7 定高转弯简单换一套宽度。规范第Ⅲ部分的 PBN 转弯保护通则规定，TA/H 转弯使用风螺旋/边界圆方法，早/晚限制按 PBN 转弯表确定。

对于 TA/H 离场接 CF 或 DF，表Ⅲ-2-2-1给出的基本逻辑是：

- 最早限制可从跑道可用起飞距离起点向前考虑（固定翼 600 m 早转弯保护背景）；
- 最晚限制由从 DER 上方 5 m 开始按规定 PDG 到达指定高度的位置，再叠加飞行员反应时间和建立坡度延时确定。

因此 B5 定高转弯至少应包含：

`DER/跑道起点 → PDG/TNA → early/late longitudinal limits → wind spiral → post-turn segment connection → PBN primary/secondary areas`。

这与 A7 传统定高转弯的 K-K/A 点结构相似，但 PBN 保护区宽度和转弯保护采用 XTT/ATT/1/2AW 体系，不能直接把 A7 几何平移过来。

### 5.5 B5 定点转弯 FlyOver-DF

该模式从名称上已经明确组合了两个概念：

- Fly-over 决定航路点处的转弯早/晚限制；
- DF 决定转弯后飞向下一定位点的航迹包络。

因此 B5 这一模式极可能与 B2 共享大量几何。合理的逆向顺序应该是：

先恢复 B2 的 `FlyOver-DF` 几何；
再看 B5 是否只是为其增加了 DER/PDG/OIS/障碍物评价。

如果 B5 内部复制了一套 B2 算法而没有调用共享方法，也应如实记录，这对以后重构尤其重要。

### 5.6 障碍物评价

规范 PBN 转弯障碍物评价中，KK′位于最早转弯点且垂直于入航航迹，转弯爬升时应从最早转弯处测量障碍物距离。因此 B5 的“转弯区评估”应重点查：

- KK′如何生成；
- 障碍物到 KK′/转弯起始边界的最短距离；
- OIS/PDG 与 MOC 的计算；
- 主区、副区内 MOC 是否按一般规则折减；
- 转弯前直线段是否单独评估。

帮助把“转弯区评估”和“直线段评估”分开，说明旧软件已经意识到两类障碍物必须采用不同距离基准和超障公式。这里非常值得恢复成两个独立业务函数，而不是只追“一键评估”总入口。

## 6. B1/B2/B5 与 A1/A7 的真实依赖假设

目前可形成如下业务依赖图：

```text
A1 WindSpiral
    └─ 提供基础转弯风影响几何能力

B1 FlyBy
    ├─ TurnParameterControl
    ├─ ATT / 前后半宽
    ├─ FlyBy early/late limits
    ├─ 多风螺旋最不利包络
    ├─ 15° / 30° / A/2 衔接
    └─ NN′ / KK′

B2 FlyOver-DF
    ├─ TurnParameterControl
    ├─ ATT / 半宽
    ├─ FlyOver early/late limits
    ├─ 多风螺旋最不利包络
    └─ DF 下一定位点切线/早转弯连接

B5 PBN Departure
    ├─ PBN initial straight area
    ├─ TA/H turn geometry
    │    └─ 可能与 B2 共用外侧风螺旋/DF连接
    ├─ FlyOver-DF
    │    └─ 很可能复用 B2
    ├─ straight obstacle evaluation
    ├─ turn obstacle evaluation
    └─ controlling obstacle / marking
```

A7 与 B5 的业务目标相同，都是“离场保护+越障”，但坐标/转弯几何不能简单视作同一算法：A7 使用传统导航定位容差和传统转弯保护准则；B5 使用 PBN 的 XTT/ATT/1/2AW 和 PBN 转弯保护准则。真正可复用的更可能是底层坐标、风螺旋、交点/切线、多段线构造、障碍物距离和 MOC 等基础函数。

## 7. 本阶段暴露出的旧软件自动化边界

B1/B2 的窗口形态揭示了旧 WsTools 的典型特点：

设计人员自己选择规范上下文和参数，软件做几何。

例如同样是 PBN 转弯，设计人员仍要手工确定：

- 当前是离场、IAF/IF、FAF 还是复飞；
- 正确的 IAS；
- 设计高度；
- 风值；
- 坡度；
- 飞行员反应时间；
- 建立坡度时间；
- ATT；
- 前后航段保护区半宽。

这些本来都可以由“程序类型 + 飞行阶段 + 导航规范 + 航空器类别 + 距机场位置”自动派生。

因此未来的新软件并不一定需要重新发明 B1/B2 的几何，真正的自动化提升之一是把这些手工参数输入收回到规则引擎，让设计人员只给出程序意图和少量设计选择。

## 8. 现在可以交给 Codex 的第三批定点问题

本阶段不需要让 Codex“逆向全部 PBN 模块”，只需回答以下问题：

1. **B1 宽度语义**：证明 SW1/SW2 在代码中到底是 1/2AW、总宽还是其他宽度；给出进入边界坐标的公式。
2. **B1 纵向限制**：恢复 Fly-by 最早/最晚点公式，明确 ATT、`r*tan(A/2)`、ReactTime、BankAngleDelay 各自进入哪一侧限制。
3. **B1 多螺旋**：确认最多生成几条候选风螺旋，怎样选择/构造最不利包络；找到 ≤90° 与 >90°的分支。
4. **B1 衔接**：定位 15°、30°、A/2 三种角度规则及其 if 条件；证明 SW1≠SW2 时帮助所称“风螺旋衔接”实际执行了哪些步骤。
5. **B1 NN/KK**：恢复 NN′N″和 KK′的独立几何，确认它们是否进入评价算法。
6. **B2 DF 语义**：确认 CAD 的第三个拾取点是不是下一 DF 航路点，而非普通出航航迹端点。
7. **B2 DF 包络**：恢复“下一定位点到最不利外侧风螺旋切线”和“下一定位点到最受限早转弯点”的实现。
8. **B2 ATT=0**：证明帮助中所说的“与 PBN 定高转弯外边界相同”是否源于真实共享方法；若不是共享方法，比较两段等价算法。
9. **B5 转弯类型**：确认公开 UI 之外是否还有 Fly-by、RF 或 CF/TF 隐藏分支；如果没有，明确旧软件 B5 只实现 TA/H 和 FlyOver-DF。
10. **B5 PBN 宽度来源**：定位 XTT、ATT、1/2AW 的来源。判断是根据导航规范/距离自动计算，还是使用固定常数/用户输入。
11. **B5 组合关系**：证明 B5 的 FlyOver-DF 是否调用 B2；TA/H 是否与 B2 ATT=0 分支共用外侧边界算法。
12. **B5 评价拆分**：分别恢复“直线段评估”和“转弯区评估”的距离基准、OIS/PDG/MOC公式及控制障碍物选择；再检查“一键评估”只是顺序调用还是另有逻辑。
13. **参数默认值**：不要把 config.xml 默认值当规范。检查 B1/B2 是否有按飞行阶段自动更新坡度、风、反应/建坡时间的事件；若没有，则记录为“规范参数由用户负责选择”。
