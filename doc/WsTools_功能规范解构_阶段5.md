# WsTools 功能—规范—算法解构（阶段5）

范围：A4 传统非精密进近保护区、A5 精密进近保护区/OAS、A10 起始进近 DME 弧。  
规范基线：AC-97-FS-005（2020）。  
软件依据：`WindSpiral2026/帮助文件`、`config.xml`、`Sample/OAS参数*.txt`、根目录 README，以及 A10 效果示例图。  
本文继续遵循“规范解释业务含义，帮助文件解释作者意图，代码决定旧软件真实实现”的原则。

## 1. 本阶段的整体认识

A4、A5、A10 表面上是三个独立窗口，但从飞行程序设计业务看，它们分别对应三类基础保护几何：

- A4：VOR/NDB 航迹引导下的传统非精密梯形保护区；
- A5：ILS 精密航段、OAS、PAOAS、下滑道不工作等精密/准精密保护区；
- A10：以 DME 弧作为起始进近航迹引导，并在 IF 处接入后续直线进近的组合保护区与障碍物评价。

它们应当被视为后续完整进近程序设计系统的“几何原语与评价原语”，而不是三个完整的程序设计器。

## 2. A4 传统非精密进近保护区

### 2.1 帮助文件暴露的真实能力

命令：`Y04_导航设备保护区`

界面只暴露：
- VOR / NDB 类型；
- 初始半宽 1.0 NM / 2.0 NM；
- 扩张角；
- 左半区 / 右半区；
- 中心线；
- 外扩 15°线；
- CAD 绘制。

窗口没有：
- FAF / MAPt；
- 航段高度；
- MOC；
- 障碍物评价；
- 有 FAF / 无 FAF 的选择；
- 下降梯度。

因此 A4 更合理的定位是“VOR/NDB 保护区几何绘制原语”，而不是完整非精密进近程序设计模块。

### 2.2 VOR 与 NDB 的规范几何

规范中的传统 VOR/NDB 最后进近保护区有明确区别：

VOR：
- 导航台处总宽 2.0 NM，即半宽 1.0 NM；
- 向两侧以 7.8°扩张；
- 总宽中 50% 为主区，两侧各 25% 为副区。

NDB：
- 导航台处总宽 2.5 NM，即半宽 1.25 NM；
- 向两侧以 10.3°扩张；
- 主、副区比例相同。

这与 A4 截图默认的“VOR + 1.0 NM + 7.8°”完全吻合。

但 A4 界面只有 1.0 NM 和 2.0 NM 两个半宽选项，没有 1.25 NM；扩张角又允许用户任意输入。因此软件并没有从 UI 层面强制保证 VOR/NDB 参数组合符合规范。

这很可能说明旧软件的设计思想是：设计人员自己知道规范参数，软件负责按给定半宽和扩张角画几何。

代码需要确认：切换 VOR/NDB 时，软件是否会自动改写半宽/扩张角；如果不会，A4 应明确归类为“人工参数驱动的几何工具”。

### 2.3 A4 与有 FAF / 无 FAF 程序的关系

规范中：

无 FAF 的 VOR/NDB 程序，主区最低 MOC 为 90 m；
有 FAF 的程序，最后进近主区最低 MOC 为 75 m。

有 FAF 时，真正用于超障的最后进近保护区只是完整 VOR/NDB 梯形区中 FAF 至 MAPt 的一部分。

A4 没有 FAF、MAPt、MOC 输入，因此它最多生成“基础梯形几何”，不能单独完成有 FAF/无 FAF 的完整程序判定。

后续新系统不应照搬这种分离方式，而应该让程序类型自动决定几何截取范围和 MOC。

### 2.4 “外扩15°线”的含义

A4 的 15°线不能和 VOR 的 7.8°、NDB 的 10.3°混为一谈。

7.8°/10.3°是导航台航迹保护区本身的扩张角；15°更可能是用于转弯后保护区向后续标称航迹扩张/衔接的辅助线。

帮助文件也明确说，单侧半区常与 15°线配合，用于转弯后飞向导航台的保护区绘制。

因此后续代码需要区分：
- `navigation divergence angle`；
- `15 degree transition line`。

如果代码里只有一个 angle 变量承担两种用途，就属于旧软件结构上的耦合点。

## 3. A5 精密进近保护区/OAS

### 3.1 A5 的功能不是一个单一 OAS 绘图器

命令：`Y05_精密进近保护区`

帮助文件列出六类绘图模式：
- GP INOP；
- PAOAS 左；
- PAOAS 右；
- OAS 面；
- PA with FAF；
- PA with FAP。

因此 A5 实际包含至少四套不同业务几何：
1. ILS 下滑道不工作；
2. 标准 OAS；
3. 平行进近障碍物评价面 PAOAS；
4. ILS 中间航段与精密航段在 FAP/FAF 条件下的完整平面保护区。

### 3.2 A5 与独立 OAS 参数生成软件的关系

根 README 明确把 PANS-OPS-OAS 参数生成软件作为 WindSpiral 之外的独立组成部分，并提供 `WsOasPara.exe`。

A5 帮助则提供 OAS 参数导入/导出功能。

这说明 A5 的主要职责很可能是“消费 OAS 参数并构造 CAD 几何”，而不是完整重新实现 ICAO OAS 参数生成器。

代码需要验证：
- A5 是否直接查询 `oas.db`；
- 还是仅使用用户导入/已有的 A/B/C 系数；
- `AppType/CAT/GP/LocDistance/RDH/Wing/Wheel` 是否会触发系数重新计算或修正。

### 3.3 OAS 面数据结构已经非常明确

`config.xml` 和样例参数文件都包含：
- W；
- WS；
- X；
- Y；
- Z；
- 每个面 A/B/C 三个系数。

规范中标准 ILS OAS 使用：

`z = A*x + B*y + C`

描述 W、W*、X、Y、Z 等面。

软件中的 `WS` 几乎可以确定对应规范中的 `W*`。

样例进一步支持这一判断：
- CAT I 样例的 WS 基本为空/占位；
- CAT II 普通模式同样没有有效 W*；
- CAT II AUTO 样例中 WS 出现真实系数。

规范规定 CAT II 自动耦合时，可以通过增加 W* 面并调整 X 面体现自动驾驶仪提高的航道保持性能。因此这里已经具有很强的业务映射证据。

### 3.4 OAS 系数与输入参数

A5 同时保存：
- GP；
- LOC 至入口距离；
- RDH；
- 机型；
- 半翼展；
- 轮/天线垂直尺寸；
- 复飞梯度；
- OAS A/B/C 系数。

规范规定这些因素都可能影响 OAS 系数。

所以后续代码不能只查“如何画 OAS 多边形”，还必须验证输入参数与系数之间是否存在真实计算关系。

### 3.5 PAOAS 左/右已经可以直接解释

A5 / `FormPaoasEvl` 中存在：

- P1：A=0.0524，B=0.091，C=5；
- P2：A=0，B=0.091，C=15。

其中 0.0524 约等于 `tan(3°)`。

这与规范 PAOAS 表中的 P1/P2 常数完全吻合：

- P1：A = tanθ，B = 0.091，C = 5；
- P2：A = 0，B = 0.091，C = 15。

因此 A5 的 PAOAS 左/右可以基本确定是在跑道某一侧绘制 P1/P2 平行进近障碍物评价面。

左/右只是相对于跑道/相邻跑道一侧的镜像选择，不是两套不同数学模型。

### 3.6 GP INOP 的业务含义

规范明确规定：ILS 下滑道不工作属于非精密进近程序。

其最后进近/起始复飞保护区由 ILS CAT I OAS X 面的外侧边界确定；当没有实际下滑道时，用 3°角确定 OAS 300 m 等高线。之后直线复飞区还会在一定位置转为 15°向外扩张。

因此 A5 的 GP INOP 很可能并不是“关闭 GP 后仍画普通 OAS”，而是根据 OAS X/Y 几何生成 LOC-only / GP INOP 的二维保护区。

Codex 应直接寻找：
- CAT I OAS X 外边界；
- 3°替代 GP；
- 300 m 等高线；
- 15°复飞扩张。

### 3.7 PA with FAP

规范中普通 ILS 精密航段从 FAP 开始。

FAP 是前序航段最低高度与标称下滑道的交点。

中间进近区在进入 FAP 时要逐渐收缩到 OAS X 面在 FAP 处的宽度，副区宽度到 FAP 逐渐减为零。

因此 `PA with FAP` 很可能表示普通的：

`IF / 中间段 → FAP → 精密航段 OAS`

其 UI 中的 `中间段长度` 应参与 IF 到 FAP 的保护区构造。

### 3.8 PA with FAF

规范允许在 FAP 设置“下降定位点”，用于排除 FAP 之前某些障碍物的影响。

一旦设置，这个点同时成为 FAF；精密面的中间段延伸在该处终止。

下降定位点最大定位容差为 ±0.9 km（±0.5 NM）。

A5 中恰好存在：
- FAF 高度；
- FAF 容差；
- `PA with FAF`。

因此一个很强的解释是：`PA with FAF` 对应“FAP 同时设置下降定位点/FAF”的精密进近保护区构造，而 `PA with FAP` 对应普通无下降定位点的 FAP 情况。

这需要 Codex 验证两个模式在以下地方的真实差异：
- 精密面向中间航段的延伸终止位置；
- FAF 容差最早点/最晚点如何使用；
- 是否存在 15% 梯度面相关处理；
- 中间保护区截断方式。

### 3.9 A5 更像“绘图区”而不是“评价器”

帮助文件只强调 CAD 绘图和参数导入/导出，没有“一键评估”和障碍物列表。

因此 A5 应先视为保护面/保护区构造工具。

真正的 OAS 障碍物评价更可能位于 `FormOasEvl`、B4 PBN-ILS 或其他评价窗口中。

这对逆向任务拆分很重要：
- A5 重点恢复几何；
- FormOasEvl 重点恢复 OAS 穿透和 OCH；
- 不要把两个功能强行合并成一个窗体逻辑。

## 4. A10 起始进近 DME 弧

### 4.1 A10 比帮助文字展示得更复杂

命令：`Y10_起始进近DME弧`

帮助文件列出的输入：
- 导航台位置；
- 呼号；
- IF 位置；
- IAF 方向；
- MOC；
- 屏幕障碍物；
- 标注距离；
- 一键评估；
- CAD。

A10 效果图显示，它并不只画一段 DME 圆弧。

图中同时存在：
- 导航台；
- DME 圆弧和多层同心保护边界；
- IAF；
- IF；
- IF 之后向导航台方向延伸的直线保护区；
- FAF；
- 障碍物点；
- 主区/副区评价结果。

因此 A10 实际很可能是“DME 弧起始进近 + IF 后中间/最后进近衔接 + 障碍物评估”的组合工具。

### 4.2 “IAF方向”不是直接 IAF 坐标

从效果图看，用户输入的 IAF 方向点与导航台形成一条射线，而真正 IAF 位于该射线与 DME 标称圆弧的交点。

IF 已经给定，因此：

`DME arc radius ≈ distance(navaid, IF)`

再用 IAF 方向确定圆弧起始方位。

效果图中的 `D20.5DHT` 也支持这种解释：软件根据导航台呼号和 IF 至台距离自动形成 DME 弧标注。

这需要代码验证，但几何含义已经相当明确。

### 4.3 DME 弧的规范保护区

固定翼起始进近 DME 弧：
- 最小弧半径 7 NM；
- 圆弧应在 IF 或之前加入后续航迹；
- 与后续航迹夹角不得超过 120°；
- 大于 70°时需要提供至少 2 NM 的提前径向线。

起始进近保护区：
- 主区在航迹两侧各 2.5 NM；
- 主区外侧再各有 2.5 NM 副区；
- 主区 MOC 300 m；
- 副区 MOC 从 300 m 线性降至 0。

A10 截图中的 MOC 默认值正是 300 m，而且障碍物结果表明确区分“主区/副区”。

因此 A10 中至少应存在：
- 点至圆心距离；
- 点相对弧段的角度范围；
- 径向偏差；
- 主区/副区判定；
- 副区 MOC 线性折减。

这可能与 A9 的通用主副区评估算法共享，也可能是单独重复实现，需要 Codex 证明。

### 4.4 DME 弧到 IF 的转入

规范要求圆弧在 IF 或之前加入后续航迹，并限制转入角。

A10 已知三个输入足以确定：
- 圆心；
- 弧半径；
- IAF 方位；
- IF；
- IF 后的径向/航迹方向。

因此软件可以完全自动生成弧段，而不需要用户手工画圆弧。

代码需要确认：
- 弧方向如何判定；
- 大于 70°/120°是否有检查；
- 是否自动生成提前径向线；
- 是否只负责画几何而不做合规性警告。

### 4.5 IF 后的直线段是 A10 的关键隐藏能力

效果图中 IF 后明显存在直线保护区，并且出现 FAF。

但帮助页完全没有 FAF 输入。

因此旧代码必然还存在一个帮助文件未充分说明的规则，用于确定：
- IF 后航迹；
- FAF 位置；
- 中间航段保护区；
- 最后进近保护区。

规范的一般中间进近准则为：
- 中间航段从 IF 到 FAF；
- 长度通常宜不小于 5 NM，最佳 10 NM；
- IF 处总宽最大 10 NM，向 FAF/FAP 处逐渐缩小；
- 主区 MOC 150 m，副区向外线性减至 0。

效果图中 FAF 看起来是由软件自动生成，因此代码必须重点查：
- 是否固定采用 5 NM 中间段；
- 是否依据 IF-DME 距离推算 FAF；
- 是否把导航台本身作为 MAPt/最后进近参考；
- 是否调用 A4 的 VOR/NDB 梯形保护区构造。

这是 A10 当前最值得“破甲”的地方。

### 4.6 A10 可能组合了三种 MOC

如果效果图中的直线部分同时覆盖中间航段和最后进近，那么理论上可能出现：
- 起始进近：300 m；
- 中间进近：150 m；
- 有 FAF 最后进近：75 m。

A10 障碍物表中的 MOC 数值既有 300，也有较小值，而且副区会进一步折减。

目前不能仅凭截图断言它确实同时实现 300/150/75 三套 MOC，但这是一个非常明确的代码验证目标。

若代码中确实出现 `300 / 150 / 75` 三段式判断，A10 就应重新定义为一个小型的传统 VOR/DME 进近组合评价器，而不只是“DME弧工具”。

## 5. A4、A5、A10 与前序模块的依赖关系

目前可以形成以下候选共享结构。

### A4

`VOR/NDB facility`
→ 基础梯形保护区
→ 左/右半区
→ 主副区边界
→ 15°辅助衔接线

### A5

`OAS coefficients`
→ W/W*/X/Y/Z 面
→ 等高线/平面边界

`IF / intermediate width`
→ FAP/FAF 处 OAS X 面宽度
→ 中间航段收缩

`PAOAS P1/P2`
→ 平行进近外侧评价面

`GP INOP`
→ CAT I OAS X/Y 几何
→ LOC-only 保护区

### A10

`Navaid + IF`
→ DME radius

`IAF direction`
→ IAF on DME arc

`DME arc`
→ 初始进近主/副区
→ 300 m MOC

`IF`
→ 中间航段
→ 自动 FAF ?
→ 最后进近保护区

因此后续代码恢复应该重点寻找下列公共函数：
- trapezoid / expanding protection area；
- primary-secondary polygon；
- linear width transition；
- linear MOC reduction；
- OAS plane intersection/contour；
- point-to-line / point-to-arc signed distance；
- arc sector inclusion；
- protection-area join at IF/FAF/FAP。

## 7. 本阶段新增的高价值结论

1. A4 应降级理解为传统 VOR/NDB 几何原语，而不是完整 NPA 设计器。
2. A5 的 PAOAS 常数与规范完全对得上，`WS` 极可能就是 W*。
